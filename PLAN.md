# Онлайн Квиз-Баттл — план работы

## Идея проекта

Онлайн квиз - есть ведущий, игроки и комната с кодом. Ведущий запускает матч, сервер по очереди показывает вопросы, ведёт таймер, принимает ответы, считает очки и формирует рейтинг игроков.

Главная задача — серверное ядро, которое проводит матч от начала до конца в реальном времени. 
Основная сложность не в обычном CRUD, а в конкурентности и многопоточности: десятки игроков отвечают одновременно, и сервер должен держать состояние матча потокобезопасно, с корректными таймерами и честным подсчётом. 
На защите проект показываем через Swagger, бота-симулятор и логи сервера.

## Как это работает

Банк вопросов хранится в PostgreSQL и наполняется из `Seed/quiz_seed.json`. 
Через API можно получить категории и вопросы.

Ведущий выбирает тему (категорию), создаёт комнату и получает её код (например, `123`). Игроки подключаются к комнате по коду.

Когда все готовы, ведущий запускает матч. Сервер ведёт игру по этапам: показывает вопрос, запускает таймер, принимает ответы. По истечении времени закрывает приём, проверяет ответы, начисляет очки, обновляет таблицу лидеров и переходит к следующему вопросу. После последнего вопроса формируется финальный рейтинг.

Временем управляет сервер. Дедлайн вопроса считается на сервере: ответ после дедлайна не засчитывается, повторный ответ на тот же вопрос игнорируется. При потоке одновременных ответов состояние матча не должно ломаться — за это отвечает синхронизация доступа к состоянию комнаты.

## Что нужно реализовать

* банк категорий, вопросов и вариантов ответов;
* создание комнаты и подключение игроков по коду;
* запуск матча и переходы между вопросами (машина состояний);
* серверный таймер на каждый вопрос;
* приём ответов, отсечение поздних и повторных;
* потокобезопасную обработку одновременных ответов;
* подсчёт очков и таблицу лидеров;
* финальный рейтинг матча;
* тесты игровой логики;
* бот-симулятор для демонстрации и проверки нагрузки.

## Этапы работы

> **Трекер прогресса** (на 22.07.2026): ✅ готово · 🔵 в работе · 🟡 частично · ⬜ впереди

### 1. Каркас проекта — ✅ сделано

Решение на .NET, структура, Git, сборка, логирование, работа через pull request. Проект запускается у всех участников команды, CI собирает и прогоняет тесты автоматически.

### 2. Базовые данные — ✅ готово для MVP (контент заливаем сидом, не через CRUD API)

Есть категории, вопросы и варианты ответов. Контент хранится в PostgreSQL, стартовый банк вопросов загружается из `Seed/quiz_seed.json`, через API можно получить категории и вопросы. Сущности матча, ответов игроков и результатов добавляем отдельно на этапе 4.

### 3. Комнаты — ✅ сделано

Создание комнаты и подключение игроков по коду. Код комнаты — часть игровой логики, а не только интерфейса: бот подключается так же, как обычный игрок (передаёт код комнаты и имя). После этапа видно, какие игроки в комнате и кто участвует в матче.

### 4. Ход матча (машина состояний) — ✅ сделано

Сервер сам ведёт игру по этапам: ожидание игроков → старт → активный вопрос → окончание времени → проверка ответов → обновление очков → следующий вопрос → завершение.

Переходы описываются машиной состояний с правилами: нельзя принять ответ, если вопрос ещё не начался или уже закрыт; нельзя запустить следующий вопрос, пока не обработан текущий. Сервер хранит текущий статус матча и проверяет допустимость каждого действия.

### 5. Ответы, таймеры, конкурентность — ✅ сделано

На каждый вопрос сервер запускает таймер. Пока время идёт — ответы принимаются, после дедлайна — нет. Повторный ответ игрока не засчитывается (идемпотентность). Ключевой момент — многопоточность: когда много игроков отвечают почти одновременно, обработка не должна ломать состояние матча или искажать очки. Ответы одного матча обрабатываются согласованно за счёт синхронизации.

### 6. Очки и лидерборд — ✅ сделано (упрощённо: 1 балл за правильный ответ, без бонуса за скорость и без стратегий - нужно продумать доп функционал на будущее, вынести отдельно в шаблон)

После каждого вопроса сервер считает очки. На старте — простая схема: правильный ответ даёт очки, неправильный — нет, быстрый правильный ответ даёт бонус за скорость. Правила начисления выносим в отдельные стратегии, чтобы менять схему без переписывания ядра. После подсчёта обновляется таблица лидеров: видно, кто на каком месте и сколько набрал.

### 7. Типы вопросов — ⬜ впереди (опционально)

Минимально — выбор одного ответа и да/нет. Если останется время — несколько правильных ответов, ввод текста, числовой ответ. Новый тип вопроса должен добавляться отдельным модулем (плагином), без переписывания ядра.

### 8. Бот-симулятор — ⬜ впереди

Так как полноценного фронта нет, для демонстрации и нагрузки добавляем бота-симулятора. Бот не заменяет механику комнаты — подключается как обычный игрок (код комнаты + вход в матч). На защите запустим сразу 10–20 участников и покажем, что сервер принимает ответы, считает очки и обновляет рейтинг под нагрузкой. Показать можно и вручную через Swagger, но бот проще и заодно проверяет работу при многих одновременных игроках.

### 9. Тесты — 🟡 частично (покрыты переходы, очки, поздний и повторный ответы; нет теста одновременных ответов, просмотреть покрытие тестами)

Покрываем самое важное — игровую логику:

* переходы между этапами матча;
* подсчёт очков;
* поздний ответ;
* повторный ответ;
* одновременные ответы нескольких игроков.

### 10. Инфраструктура и развитие — 🟡 частично (Docker + CI + Redis-кэш готовы; RabbitMQ/Aspire/авторизация — позже)

Поверх рабочего ядра постепенно добавляем:

* Docker для запуска проекта — есть;
* GitHub Actions (сборка и тесты) — есть;
* Redis — есть (кэш контента и списка комнат; лидерборд пока из Postgres);
* RabbitMQ для событий матча — позже;
* разрез на сервисы и оркестрацию (.NET Aspire) — позже;
* авторизацию и хранение истории матчей — позже.

Эту инфраструктуру наращиваем уже поверх работающего ядра, а не на старте.

## Как показываем на защите

1. Проверяем банк вопросов через Swagger: категории и вопросы загружены из seed-файла в БД.
2. Создаём комнату, подключаем игроков (вручную или ботом).
3. Запускаем матч.
4. Показываем, как сервер переключает вопросы по таймеру.
5. Показываем, что поздний и повторный ответы не засчитываются.
6. Показываем живую таблицу лидеров и финальный рейтинг.

Смысл демонстрации — сервер реально проводит игру.

## Что должно получиться в конце

* есть банк вопросов и категорий, создаётся комната, игроки подключаются по коду;
* ведущий запускает матч, сервер сам ведёт игру по вопросам;
* ответы принимаются только вовремя, повторные не засчитываются;
* очки считаются на сервере, лидерборд обновляется после каждого вопроса;
* по завершении есть финальный рейтинг;
* есть тесты игровой логики и бот-симулятор для демонстрации и нагрузки.

Главный результат — рабочее серверное ядро онлайн-викторины, которое можно запустить и показать в действии, а при желании нагрузить ботами и продемонстрировать работу под нагрузкой: как сервер держит десятки одновременных игроков, с какой скоростью откликается и не теряет ли ответы. 
Инфраструктура (Redis, RabbitMQ, разрез на сервисы) наращивается поверх него.

План можно корректировать, тк основан на реальной игре, поэтому отдельные пункты остаются опциональными. В конце можно отдельно проработать контроль игровой сессии в рамках одного матча, чтобы снизить риск повторного входа в игру или игры из нескольких вкладок одним участником.
